# Gerhana M0–M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Validate the core loop on paper (M0), then build the deterministic TypeScript rules engine and a bot-vs-bot simulation CLI that reports balance metrics (M1).

**Architecture:** `packages/rules` is a pure TypeScript library with no I/O. It holds the game state, the content as data, and the functions that advance a run. All randomness comes from one seeded RNG passed in by the caller. `packages/sim` is a Bun CLI that plays thousands of runs with two bots and prints a report. The server (M2) and the Godot client (M3) are out of scope here, but they will call the same `rules` functions.

**Tech Stack:** Bun (runtime, workspaces, `bun test`), TypeScript strict mode. No runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-06-gerhana-mvp-design.md`

## Global Constraints

- Two players exactly. Every number is designed for 2 players (spec §5).
- Each turn: draw 4, play exactly 2 (spec §4.1).
- Resolution order: Tahan + Bantu (P1, then P2) → Serang (P1, then P2) → enemies left to right → end-of-turn effects (spec §4.1).
- Rentan: damage taken +50%. Lemah: damage dealt −25%. Terbakar: damage = stacks at end of turn. All statuses lose 1 stack at end of turn. Damage rounds down, minimum 0 (spec §4.3).
- HP: Pendekar 42, Dalang 36 (spec §3).
- Revive after a won combat at 25% of max HP. The run is lost when both players are pingsan in the same combat (spec §4.5).
- Map: 7 steps + boss, 2 nodes per step (spec §6.2).
- Coins: 15–25 per normal combat, 40 per Elite. Shop: card 50, removal 75. Rest: heal 30% of max HP or upgrade 1 card (spec §6.2–6.3).
- Same seed + same picks must always produce the same state (spec §9).
- The rules package has no I/O, no `Math.random`, and no `Date`.
- Text is stored as translation keys (`nameKey`), never as display strings (spec §7).

## Review Focus

1. **Every target of a Serang card is already dead.** The attack moves to the leftmost living enemy. When no enemy is alive, the remaining cards do nothing, enemies do not act, and the combat is won. Covered by a test in Task 5.
2. **Invalid picks:** a duplicate card, a card not in hand, a count other than 2, a Bantu card aimed at an enemy, a Serang card aimed at an ally, a dead target, or a pick from a pingsan player. `validatePicks` rejects each with an error code and the state does not change. Covered by a test in Task 6.
3. **A steal larger than the player's coins.** The steal takes `min(coins, amount)`, and coins never go negative. Covered by a test in Task 5.
4. **Terbakar at end of turn kills the last enemy, or knocks out both players.** The first case wins the combat. The second case loses the run, even when both players drop in the same tick. Covered by a test in Task 4.
5. **Card removal would leave a deck too small to draw from.** Removal is refused when the deck has 5 cards or fewer. Drawing with fewer than 4 cards available draws what exists. A hand of fewer than 2 cards plays all of them. Covered by tests in Tasks 4 and 8.

**Interfaces:**
- Consumes: `Rng` (Task 1), content and types (Task 2), `tickStatuses` and `absorb` (Task 3).
- Produces:
  ```ts
  interface PlayerCombat { id: 0 | 1; character: CharacterId; hp: number; maxHp: number; block: number; wayang: number; statuses: Statuses; coins: number; jurusStacks: number; pingsan: boolean; draw: CardInstance[]; hand: CardInstance[]; discard: CardInstance[]; damageDealt: number }
  interface EnemyCombat { uid: string; defId: string; hp: number; maxHp: number; statuses: Statuses; patternIndex: number; phase: 1 | 2; intent: ResolvedIntent | null; stolen: { player: 0 | 1; amount: number }[]; evading: boolean; fled: boolean }
  type ResolvedIntent = Intent & { targets: (0 | 1)[] }
  interface CombatState { turn: number; players: [PlayerCombat, PlayerCombat]; enemies: EnemyCombat[]; outcome: "ongoing" | "won" | "lost" }
  export function startCombat(players: [PlayerCombat, PlayerCombat], encounterId: string, rng: Rng): CombatState
  export function startTurn(s: CombatState, rng: Rng): CombatState
  export function endTurn(s: CombatState): CombatState
  export function checkOutcome(s: CombatState): CombatState
  ```
  - `startCombat` shuffles each player's deck into `draw`.
  - `startTurn` draws 4 per player who is not pingsan (reshuffles the discard when needed, and draws fewer if fewer exist). It then picks each living enemy's intent from its current pattern (phase 2 when HP is at or below `belowHpPct`). Targets are resolved now, among players who are not pingsan. `evading` is set when the intent is `evade`.
  - `endTurn` discards hands, clears block, applies Terbakar to everyone through `absorb` (wayang still absorbs), decays statuses, then calls `checkOutcome`.
  - `checkOutcome`: `won` when every enemy is dead or fled; `lost` when both players are pingsan.
  - All functions return new objects. They never mutate their input.

**Files:**

**Interfaces:**
- Consumes: Task 3 and Task 4 exports.
- Produces:
  ```ts
  type Target = { kind: "enemy"; uid: string } | { kind: "player"; id: 0 | 1 };
  interface Pick { cardUid: string; target: Target }
  type Picks = [Pick[], Pick[]];                     // index = player id
  type GameEvent =
    | { t: "card"; player: 0 | 1; cardUid: string; target: Target }
    | { t: "damage"; to: Target; amount: number; hpAfter: number }
    | { t: "block"; player: 0 | 1; amount: number }
    | { t: "wayang"; player: 0 | 1; hp: number }
    | { t: "status"; to: Target; status: StatusId; stacks: number }
    | { t: "steal"; enemy: string; player: 0 | 1; amount: number }
    | { t: "flee"; enemy: string }
    | { t: "coinsReturned"; player: 0 | 1; amount: number }
    | { t: "pingsan"; player: 0 | 1 }
    | { t: "enemyDied"; enemy: string };
  export function resolveTurn(s: CombatState, picks: Picks, rng: Rng): { state: CombatState; events: GameEvent[] }
  ```
  `resolveTurn` assumes the picks are valid (Task 6 validates them). It ends by calling `endTurn`.

**Rules to encode (from spec §3–§5):**
- **Jurus Berantai:** before the Serang phase, a player who picked at least 1 `jurus` card gets `jurusStacks += 1`. Otherwise the stacks reset to 0. Each Serang card the player plays gets +`jurusStacks` base damage.
- **buffAttack** adds to each Serang card the target plays this turn.
- **Serempak:** a card gets `serempakBonus` when the partner also plays a Serang card at the same enemy uid this turn (the original targets, before any retarget).
- **Retarget:** a Serang card whose target is dead or fled hits the leftmost living enemy. When none remain, the card does nothing.
- **Wayang:** `wayang += hp` on the target. One wayang pool per player.
- **Enemy kills:** an enemy killed while holding stolen coins returns them (`coinsReturned`).
- **`steal`:** takes `min(coins, amount)` from the target.
- **`flee`:** sets `fled`, and the coins stay lost.
- **`drain`:** deals damage and heals the enemy by the same base amount, capped at `maxHp`.
- **`destroyWayang`:** sets the target's wayang to 0. When the target had no wayang, it applies Lemah `fallbackLemah` instead.
- **`charge`** does nothing this turn.
- **Pingsan:** a player at HP 0 becomes pingsan, and their remaining enemy attacks this turn are skipped.
- **Damage tracking:** add the HP damage each player deals to enemies into `damageDealt` (used for Pusaka in Task 8).
- **Order:** advance `patternIndex` after each enemy acts.

  ```ts
  type NodeKind = "pertarungan" | "elite" | "istirahat" | "warung";
  type MapStep = [NodeKind, NodeKind];
  export function generateMap(rng: Rng): MapStep[]                       // length 7; boss is implicit step 8
  interface PlayerRun { character: CharacterId; hp: number; maxHp: number; coins: number; deck: CardInstance[]; pusaka: string[] }
  type Phase =
    | { kind: "vote"; step: number; votes: [number | null, number | null] }
    | { kind: "combat"; node: NodeKind; combat: CombatState }
    | { kind: "reward"; offers: [string[], string[]]; pusakaOffer: string[] | null; pusakaChooser: 0 | 1 | null; done: [boolean, boolean] }
    | { kind: "rest"; done: [boolean, boolean] }
    | { kind: "shop"; offers: [string[], string[]]; done: [boolean, boolean] }
    | { kind: "ended"; result: "won" | "lost"; stepReached: number };
  interface RunState { seed: number; map: MapStep[]; players: [PlayerRun, PlayerRun]; phase: Phase }
  type RunAction =
    | { kind: "vote"; player: 0 | 1; choice: 0 | 1 }
    | { kind: "playCards"; picks: Picks }                   // both players' picks, already validated
    | { kind: "chooseCard"; player: 0 | 1; defId: string | null }
    | { kind: "choosePusaka"; player: 0 | 1; id: string }
    | { kind: "rest"; player: 0 | 1; choice: "heal" | { upgrade: string } }
    | { kind: "shopBuy"; player: 0 | 1; defId: string }
    | { kind: "shopRemove"; player: 0 | 1; cardUid: string }
    | { kind: "leave"; player: 0 | 1 };
  type RunError = "WRONG_PHASE" | "NOT_ENOUGH_COINS" | "DECK_TOO_SMALL" | "INVALID";
  export function createRun(seed: number, characters: [CharacterId, CharacterId]): { state: RunState; rng: Rng }
  export function applyAction(s: RunState, a: RunAction, rng: Rng): { state: RunState; events: GameEvent[] } | { error: RunError }
  ```

**Rules (spec §6):**
- **Map:** step 1 = `["pertarungan", "pertarungan"]`. Step 7 = `["istirahat", "istirahat"]`. Elite appears in 1–2 steps, never in steps 1–2. Warung appears at least once in steps 3–6.
- **Votes:** when both votes are in and they differ, `rng.int(0, 1)` decides.
- **After a won combat:**
  - Pingsan players revive at `floor(0.25 * maxHp)`.
  - HP carries over from the combat.
  - Coins: `rng.int(15, 25)`, or 40 for an Elite.
  - Each player gets an offer of 3 from their own pool.
  - An Elite also offers 3 Pusaka. `pusakaChooser` = the player with the higher `damageDealt` (ties go to player 0).
- **Rest:** heal `floor(0.3 * maxHp)`, capped at max, or upgrade 1 card.
- **Shop:**
  - Offers 3 cards at 50 coins each.
  - Removal costs 75 coins.
  - Removal is refused with `DECK_TOO_SMALL` when the deck has 5 cards or fewer.
- **Phase advance:** a non-combat phase moves to the next vote once both players are `done` (via `leave`, or after their choice).
- **Boss:** step 8 is the Banaspati encounter. Winning it → `ended` `won`.
- **Losing a combat** → `ended` `lost` with `stepReached`.
- `createRun` gives `CardInstance` uids as `${player}-${n}`, and new cards continue the counter.
